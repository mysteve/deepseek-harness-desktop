# 标题栏融入内嵌页面设计（悬浮窗控方案）

日期：2026-08-17
状态：已批准（用户选定"悬浮窗控，页面顶到边"方案）

## 背景

v0.2.5 后窗口已改为无边框（`decorations(false)`）+ 前端自绘标题栏（`TitleBar` 组件），
但标题栏仍是独立的一条（应用名 + 窗控按钮 + 下边框），与内嵌 dsh 页面之间有明显的"套壳感"。

## 目标

去掉独立标题栏条带，dsh 页面铺满整个窗口（顶到边缘），窗口操作能力（拖动、
最小化/最大化/关闭）以隐形悬浮层的形式保留，视觉上与页面 100% 融合。

## 实测依据（dsh 页面，2026-08-17，端口 3080 实测 DOM 几何）

- 顶带（y < 64px）可点元素全部位于左侧侧边栏区（x < 270px），y 从 ≈22px 开始：
  - 折叠态：「打开侧边栏」(10, 18, 36×36)
  - 展开态：「新建会话」(16, 24)、「收起侧边栏」(240, 22, 28×28)
- 主内容区顶带（x > 280px，y < 64px）在所有状态（折叠/展开/初始化向导/会话视图）均无可点元素。
- 右上角始终为空，窗控按钮不会压住 dsh 自身按钮。
- Tauri `drag.js`（2.11.5）：`data-tauri-drag-region="deep"` 区内可点元素（BUTTON/A/INPUT 等）
  自动放行点击、不触发拖拽；双击拖拽区自动最大化/还原。
- 外壳 z-index 惯例：drawer z-30 > overlay z-[25] > toggle z-20。

## 设计

新组件 `WindowChrome`（替代 `TitleBar`），常驻悬浮于最上层（z-40）：

1. **顶部 32px 全宽透明条**（`absolute inset-x-0 top-0 z-40 h-8`）：
   - 左段 288px `pointer-events-none`：dsh 侧边栏顶部控件区点击穿透给 iframe，不受影响。
   - 其余区段 `data-tauri-drag-region="deep"`：按住拖动窗口、双击最大化/还原。
     该段横跨调试抽屉（z-30）顶部——抽屉顶部 32px 为 padding/标题（无可点元素），
     被覆盖无副作用，且抽屉展开时窗口仍可拖动。
2. **右上角窗控按钮**（最小化 / 最大化-还原 / 关闭）：平时背景透明、图标用 text-muted，
   hover 才显形（关闭 hover 红）。按钮是可点元素，与拖拽区共存无需特殊处理。
3. **无应用名、无边框、无背景**。窗口标题仍由 Rust 侧 `.title()` 提供（任务栏/Alt-Tab）。
4. 布局（`app.tsx`）：根节点 `relative flex h-screen w-screen flex-col overflow-hidden`，
   dsh iframe（`HarnessWebview`）占满全窗，`WindowChrome` 作为 absolute 悬浮层最后渲染。

## 边界情况

- 安装中 / 错误态：`WindowChrome` 常驻渲染，Setup 居中卡片与顶带无冲突。
- iframe 错误覆盖层（z-[1]）低于窗控件层，不遮挡重试按钮。
- 调试抽屉（z-30）在窗控件层（z-40）之下：抽屉顶部 32px 被隐形拖拽条覆盖（无交互损失），
  窗控按钮悬于抽屉右上角之上，始终可达。
- 双击拖拽条最大化由 Tauri 注入脚本处理，无需前端代码。

## 不做的事（YAGNI）

- 不给抽屉/页面注入额外拖拽把手（拖拽条已覆盖全部状态）。
- 不改动 Rust 侧（decorations/shadow/右键菜单禁用逻辑保持现状）。
- 不做按钮随抽屉开合的位移动画（按钮位置与抽屉顶部无冲突）。
